# 架構與後續擴充

## 分層

- data：事件資料、站點位置、角色與選項。
- engine：純規則，引擎不依賴 DOM/WebGL。普通主線、接管、插單、支線與夜班使用同一事件契約。
- navigation：純矩形碰撞與格點 BFS。renderer 與單元測試使用同一份佈局，不讓測試與實際碰撞各寫一套。
- world：Three.js 渲染、程序生成模型、服裝、攝影機、動作、點地板尋路。畫面使用真正 3D 幾何與光影，不是圖片平移。
- app：按鍵/站點互動、對話、任務面板、收藏與 localStorage。

一般腳本先載入 data/engine/navigation；app/world 為 ES modules，使用本機 vendor/three.module.js 與 three.core.js。沒有外部 CDN 或 API。

## 事件契約

事件包含唯一 id、station、role、title、body、options。選項含 label、text、delta，以及可選的 flag/flag2、trigger、requiredRole、finish、night。普通路線由 routes[id].events 陣列定義。

`event(state)` 的優先序：已登錄結果的原事件 → 進行中的支線 → 待處置插單 → 夜班 → 主線。結果快照固定事件，避免支線進度增加後錯顯示下一個站點。

`choose` 登錄一次後進結果頁，`advance` 才推進。主線第3、6個節點加入插單；每輪保留兩個種子抽樣 ID。支線有獨立索引，完成後回原主線，不能重複刷同一節點。

CQE requiredRole 選項觸發 hidden takeover：保留 paused 原案與時間、目前數值、支線、插單進度，改 route=brand/step=0。隱藏線的時間不回到早上，按接管時刻延伸至18:00。原主線不會因接管自動算完成；交接是否完成是隱藏結局條件之一。

## 空間與更衣

工廠座標 x -25..25、z -17..17。管制區 x>11、z<1，隔離牆與西側門形成唯一入口。鎖門是碰撞判定的一部分。更衣允許開門並改模型；通過門外足夠距離後關門、換回工作服，避免身體還在門中就關門而卡住。

移動的畫面方向與等角鏡頭一致。自動尋路與鍵盤移動都走同一碰撞判定。手機使用 pointer capture 方向按鈕，離開頁面/失去焦點停止移動。每次換裝有紀錄，重復點已換裝狀態不會增加成本。

家中場景是另一個 group 與碰撞範圍，開始夜班時切換，玩家位置也獨立重設。兩個場景共享角色與指標。

## 保存與內容安全

狀態版本1、自動儲存位置/服裝/結果快照、收藏分開儲存。失效存檔重建，文字輸出轉義，無外部追蹤/傳輸。引擎不是防作弊伺服器，玩家可修改本機資料。交接紀錄最多保留最近120筆，避免換裝來回無限放大存檔。

新增區域時必須同時調整 stations、幾何模型與 navigation 碰撞布局，並跑站點可達性測試。後續可以把事件時鐘改成跨日班表、把永久職能搬到career狀態、加入自主NPC、模型動畫、音效、圖面/測試謎題與存檔匯出匯入。不要加入真實個資或現場測試規格。
